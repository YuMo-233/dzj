# 扭曲做成独立样式字段，并挂在字形绘制出口

逐字出现（`typewriter`）与逐字变形（`distort`）是两件事，所以各占一个样式字段：能单独用，也能叠加。变形只能在**字形绘制的那一刻**做——`FormattedCharSequence` 只带"下标 + 样式 + 码点"，`BakedGlyph#render` 也没有逐字形变换参数——而 1.21.1 里"一个字形被画出来"的唯一出口是 `Font$StringRenderOutput#accept`，普通绘制与 8 倍描边都走它。因此在这里注入：进入 `accept` 时给 `x`/`y` 加上这一字的位移，返回前再减掉；光标累加（`x += advance`）夹在中间，净值守恒，后续字符不会被带偏，一处注入就覆盖普通、阴影与描边。

## Considered Options

- **把扭曲放进 `typewriter` 对象**：写法少一层，但普通文本就用不了变形，而"空灵/诡异"恰恰常与逐字出现分开使用，**不采用**。
- **自己接管文字绘制**：等于重写排版、换行与字形缓存，收益相同、代价高得多，**不采用**。
- **每帧重新随机**：更毛躁但会闪，且同一段文字每次观感都不同、无法调参，**不采用**（改为固定种子 + 时间函数）。

## Consequences

- 相位基准分两种：波浪用**像素横坐标**（沿整行连续，不受组件被拆成几段影响），漂移/抖动用**参数哈希 + 字符下标**（同一段文字观感可复现）。
- 扭曲参数进入判等身份（见 [0006](0006-打字机身份参与样式判等.md)），否则"只差扭曲参数"的同名物品会继续堆叠。
- **客户端 mixin 无法在无头环境验证**：`Font$StringRenderOutput` 只在客户端加载，注入点写错会在启动时直接报 MixinApplyError。发布前必须在真机启动一次客户端确认。
- 阴影/描边会跟着字形一起扭曲（它们在同一段里按 `x + 偏移` 画）；下划线之类"效果"的位置是在偏移窗口内记录的，因此也会跟着走。

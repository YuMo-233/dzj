# 逐字指令只在服务端登记与执行，客户端仅回报"第几个字符"

`command` 每打出一个字符执行一次。如果把指令文本下发给客户端、再让客户端把"要执行的命令"发回来，等于给每个客户端一个任意命令执行通道。所以：指令文本只在**服务端线程解码样式时**登记（会话 → 指令，10 分钟 TTL），客户端只可能上报"会话 + 第几个字符 + 该字符"，服务端把字符消毒成单个可打印字符后回填 `%c`/`%i`/`%n` 再执行。

执行以观看者身份、权限封顶 2 级、输出完全静默（`/playsound` 之类不会再给玩家回显），并带每人每秒 100 次的速率上限；会话内序号必须严格递增，重复或迟到的回报被丢弃。

## Consequences

- 由**客户端**提交的组件（告示牌、成书）是在 Netty 线程解码的，不满足"服务端线程"这一条，因此不会登记，也就无法借道执行指令。这条安全边界依赖"信任只在服务端线程成立"，改动登记条件时必须一并复核。
- 跳字不设上限：掉帧、切标签页、聊天栏合并都会一次跳过很多字符，卡死跳字会让动画后半程的指令永久不再触发；指令文本始终留在服务端，客户端只能推进序号。

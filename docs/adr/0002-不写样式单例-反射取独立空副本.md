# 不往 `Style.EMPTY` 写打字机数据，改为反射取一份独立空样式副本

原版 `Style.create` 在字段全空时返回**全局单例** `Style.EMPTY`，而 `Style` 没有任何公开的构造入口：想"造一个空样式"的常见写法（`Style.EMPTY.withBold(true).withBold(null)`）会被 `checkEmptyAfterChange` 折回那个单例——它判断的是 `equals(EMPTY)`，不是身份。而 `{"text":"x","typewriter":{...}}` 这类"只有打字机、没有别的样式字段"的组件必然解码成 `EMPTY`，此时若把数据挂在解码结果上，就写到了全局单例上：游戏里**所有**文本都会变成打字机。

因此挂载前一律先用反射构造一份字段全空、但不是单例的样式副本（`TypewriterStyleCodec.copyOf`：反射调用 `Style` 的私有构造器，再让原样式 `applyTo` 到它上面），把数据写在副本上，绝不改动传入的样式对象。

## Consequences

- 反射不可用时（构造器找不到、`setAccessible` 被挡）退化为普通文本：逐字效果静默失效，启动日志里有一条 WARN。这是刻意的取舍——宁可不动画，也绝不污染全局样式。
- 这段"看起来可以简化"的代码不要简化：直接把数据写到 `EMPTY` 上能通过任何单元测试，却会在真实游戏里炸掉所有文本。

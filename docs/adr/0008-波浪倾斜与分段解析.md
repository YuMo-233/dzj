# 波浪倾斜字形 + § 码分段解析

波浪要"真"起来，除了位移还得让每个字形顺着波形歪一歪；而 § 码（`§$`/`§^`）则是给"只能用纯文本"的地方（存档名、书、告示牌、数据文件）一条开效果的捷径。两件事分别落在两处挂载点上。

## 1. 倾斜：替换 `renderChar` 的 pose，而不是重写顶点

波形位移本身不携带"方向"信息——相邻字形高度不同，但没有一个平面变换能让字"跟着波转"。字形四角的绘制点是 `BakedGlyph#render` 在 `accept` 里直接用 `x`/`y` 现算的，所以重写顶点意味着复制整个字形网格算式。但调用 `accept` 时还传了一个 `Matrix4f pose`——在 1.21.1 里它**不是** `StringRenderOutput` 的 final 字段、而是 `renderChar` 的一个参数。于是用 `@Redirect` 把唯一的 `renderChar` 调用换成"绕当前笔位 {x, y} 旋转过的矩阵"即可：

```
angle = clamp(atan(k·cos(phase)), ±tilt°)，k = amplitude·2π / wavelength
```

倾斜角由**位移沿行方向的斜率**推导（`d(位移)/d(x) = k·cos(phase)`），`tilt`（度）当上限截断——改 `amplitude`/`wavelength` 时角度自洽跟变，玩家不用再调一个数。枢轴取笔位原点：字形底部钉住、上半身摇，相邻字不易叠。阴影与字形本体在**同一次** `renderChar` 里画，自动一起转。

## Considered Options

- **重写 `BakedGlyph` 顶点**：完整复制四角 UV/坐标网格，脆弱且重复实现，**不采用**。
- **倾斜角用独立参数**（写死角度）：改 amplitude/wavelength 时波形与倾斜脱节，**不采用**。
- **逐字形旋转写入 `x`/`y` 预变形**……不成立：旋转不是平移，无法用两个标量表达，**不采用**。
- **枢轴取字形中心**：需要额外注入取 advance，且字形中心旋转会让相邻字在倾斜时更易重叠，**不采用**（取笔位原点）。
- **把 § 码挂进每个文本通道**：分通道适配，书/告示牌/物品名/世界名各写一遍；**不采用**（挂在 `MutableComponent#visit` 之下——一切"字符串 → 可绘制文字"的必经出口）。

## Consequences

- **`underline`/`strikethrough` 等 `BakedGlyph$Effect` 不跟随倾斜**：它们由 `finish()` 按未旋转的 pose 统一画，跟随需给每个 Effect 也挂矩阵，改动面明显变大。小角度下几乎无感，记为已知限制。
- **`Matrix4f.rotateAround(quat, ox, oy, oz)` 是 JOML 1.10.5 的实际签名**（不是 `(AxisAngle4f, Vector3f)`）；`AxisAngle4f` 不实现 `Quaternionfc`，要包一层 `Quaternionf().rotateAxis(...)`。
- **`renderChar` 是 `Font` 的包私有方法**，从外部包调用前必须先 `@Shadow abstract` 声明。
- **§ 码只在渲染层解析**：数据（NBT、存档名文件、JSON 文本）里保留 `§$` 原样，显示时才变成波浪；多人在线文本的 `§` 仍受原版聊天安全过滤（输入框打不进 `§`，与原版色码同等待遇）。
- **其它 `§x` 不在解析范围**：原版色码 `§a` 等会按字面显示（这段文本要颜色请用 JSON 样式字段）。§ 码不识别 `typewriter`，只认波浪/抖动，天然不会触发指令执行。
- **§ 码效果与 `typewriter` 组合暂不切片**：§ 拆段只发生在 `TypewriterRender.plain`（无打字机的通道）；打字机激活的文本按 `emit` 原样输出，§ 码显示为字面。组合支持后补，记为已知限制。
- **倾斜/§ 码都只在客户端**，服务端仍只存数据；`tilt` 与 § 码都不参与判等身份（`Style.equals` 仍只看 JSON 字段里的 distort 参数）。
